# ADR-047 — Выгрузка исходников проекта: `GET /projects/{pid}/source` → zip

**Статус:** Accepted · **Дата:** 2026-09-02 · **Sprint:** клиентский API (запрос iOS)

Добавляет read-only эндпоинт поверх уже существующих артефактов ревизий. Не меняет пайплайн сборки, формат `source.tgz`, схему БД и GC проектов ([ADR-011](ADR-011-project-soft-delete-and-gc.md)).

## Context

Приложению нужно отдавать пользователю исходники сгенерированного сайта — сохранить или поделиться ими из iOS share sheet.

Артефакт для этого уже есть и хранится штатно: каждая ревизия ссылается на упакованное дерево Agent 3 (`revisions.source_artifact_ref` → S3-ключ `sources/{job_id}/source.tgz`, [ADR-014](ADR-014-post-delivery-edits-and-revisions.md)); из него же выполняется пересборка при откате (`app/deploy/rollback.py`). Наружу артефакт не отдавался: API оперировал только `live_url` и историей ревизий.

Обсуждались три способа доставки: zip через API, отдача `source.tgz` как есть и presigned-ссылка в объектное хранилище. Владелец выбрал zip через API.

## Decision

### A. Zip, а не tar.gz

`GET /projects/{pid}/source` отдаёт `application/zip` с `Content-Disposition: attachment; filename="{pid}-rev{N}.zip"`. Перепаковка выполняется на лету из `source.tgz` ревизии.

Причина — потребитель: iOS открывает и шарит zip штатными средствами, tgz требует стороннего распаковщика. Хранилище при этом не меняется: канонический формат ревизии остаётся `source.tgz` (из него собирает воркер), zip существует только как форма выдачи.

### B. Через API, а не presigned-URL

Ссылка напрямую в объектное хранилище потребовала бы выставить MinIO наружу (Traefik-роутер, домен, TLS) и ввела бы второй канал доступа к данным пользователя со своей моделью аутентификации. API-путь переиспользует уже работающий Bearer-гейт и tenant-фильтр `get_project` (чужой/удалённый проект → `404`, существование не раскрывается).

Цена решения — трафик и память api-процесса на время ответа (§Consequences).

### C. Состав архива и границы

- **По умолчанию — текущая активная ревизия** (`projects.current_revision_id`); query `revision_no` (≥1) выбирает конкретную из `GET /projects/{pid}/revisions`.
- **Служебный манифест сборки `.build.json` исключается** — это контракт воркера (`build.command` / `build.output_dir`), а не файл проекта; тот же пропуск, что в `safe_extract_tgz`.
- **Не-regular tar-члены отвергаются** — защита сохраняется на выдаче, хотя `pack_source_tgz` пишет только regular files.
- **Предел распакованного размера** (`SOURCE_ZIP_MAX_TOTAL_BYTES`, 64 МБ) → `409`: патологический архив не должен молча съесть память процесса.
- **`404`** — чужой/несуществующий/удалённый проект, отсутствующая ревизия и проект, у которого ещё нет ни одной опубликованной ревизии.

## Consequences

**Плюсы:**
- Пользователь получает исходники в формате, который его устройство открывает само; никакой новой инфраструктуры и ни одного нового секрета.
- Артефакт берётся тот же, из которого собирается сайт, — отданное совпадает с опубликованным побайтово (плюс исключённый служебный манифест).
- Доступ ограничен тем же tenant-фильтром, что и остальные project-эндпоинты: отдельной модели прав заводить не пришлось.

**Минусы:**
- Ответ формируется в памяти api-процесса (скачивание из S3 + перепаковка), поэтому большой архив занимает память на время запроса; предел в 64 МБ ограничивает ущерб, но не делает выдачу потоковой.
- Каждое скачивание — это чтение из объектного хранилища: частые повторные запросы клиента бьют по S3-трафику. Кэша на выдаче нет.
- Перепаковка тратит CPU на каждый запрос; результат не кэшируется, хотя `source.tgz` ревизии неизменен. Кандидат на будущее — класть zip рядом в хранилище при первом обращении.

## Alternatives

- **Presigned-URL в MinIO.** Отвергнута владельцем: требует публикации хранилища наружу и второго канала аутентификации ради экономии трафика через API.
- **Отдавать `source.tgz` как есть.** Дешевле (без перепаковки и без предела на память), но перекладывает распаковку на пользователя iOS. Отвергнута владельцем.
- **Отдавать собранную статику (`dist.tgz`).** Отвергнута: запрошены именно исходники — собранная статика не редактируема и бесполезна как «исходный код сайта».
- **Складывать zip в хранилище при публикации ревизии.** Убрала бы CPU-стоимость выдачи, но удваивает хранение каждой ревизии ради функции, которой пользуются редко; отложено до появления реальной нагрузки.
