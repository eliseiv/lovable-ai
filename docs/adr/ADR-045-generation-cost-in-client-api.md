# ADR-045 — Стоимость генерации в клиентском API: `cost_usd` задачи и среднее по сервису

**Статус:** Accepted · **Дата:** 2026-09-02 · **Sprint:** клиентский API (запрос iOS)

Расширяет клиентский контракт (`GET /jobs/{jid}`, `GET /billing/me`) двумя read-only полями. Не меняет cost-ledger ([03-data-model → llm_usage](../03-data-model.md#llm_usage-cost-ledger)), биллинг-логику и квоты; миграции не требует.

## Context

Приложению нужно показывать, во сколько обходится генерация. Данные для этого в системе есть с самого начала: `app/pipeline/cost.record_usage` пишет строку `llm_usage` на каждый вызов агента и тем же действием инкрементирует агрегат `generation_jobs.spend_usd`. Наружу, однако, не отдавалось ничего: `JobStatusResponse` нёс только состояние/ретраи/`live_url`, `BillingMeResponse` — тариф и квоты.

Запрос владельца сформулирован как «чтобы в каком-нибудь ответе приходила стоимость одной генерации/запроса», и уточнён как **обе** величины: стоимость конкретной задачи и типичная стоимость генерации.

Это разные вопросы, и смешивать их в одном поле нельзя: первый — «сколько стоила ЭТА задача» (растёт по ходу, окончателен в терминале), второй — «сколько обычно стоит генерация» (характеристика сервиса, нужна до запуска задачи).

## Decision

### A. `cost_usd` в `GET /jobs/{jid}` — фактическая стоимость этой задачи

Значение — `generation_jobs.spend_usd`, тот самый агрегат, по которому работает budget-гард. Никакого отдельного пересчёта по `llm_usage`: два источника одной величины разошлись бы (гард видел бы одно, клиент — другое).

Поле неотрицательное и монотонно растёт в пределах задачи; в `LIVE`/`FAILED` оно окончательное. Оплаченные вызовы учитываются, даже если попытка кончилась невалидным выводом и была ре-семплирована ([ADR-020 §I.3](ADR-020-agent-output-contract.md)) — клиент видит реальную себестоимость, а не «стоимость удачных вызовов».

### B. `avg_generation_cost_usd` в `GET /billing/me` — среднее по сервису за 30 дней

Считается по терминально успешным (`LIVE`) джобам **генерации** с ненулевым расходом за последние 30 дней.

- **Почему окно, а не «за всё время».** Цены моделей и состав пайплайна меняются (переключение провайдера — [ADR-032](ADR-032-llm-provider-abstraction-openai.md), смена `AGENTn_MODEL`); среднее по всей истории показывало бы стоимость по уже неактуальным тарифам.
- **Почему только `LIVE`.** Незавершённая или упавшая джоба — это не «дешёвая генерация», а отсутствие результата; включение занизило бы величину ровно в тот момент, когда сервис работает хуже.
- **Почему `kind='generation'`.** Правки (`edit`) дешевле генерации и разбавили бы ответ на вопрос «сколько стоит сделать сайт».
- **Почему исключены нулевые.** Ноль в `spend_usd` при `LIVE` — это публикация без вызовов модели (откат на готовую ревизию) либо аварийный путь; такие строки занижают среднее, ничего не говоря о стоимости генерации.
- **Почему `null`, а не `0.0` при отсутствии данных.** «Неизвестно» и «бесплатно» — разные состояния; `0.0` клиент показал бы пользователю как факт.

**Величина по сервису, а не по пользователю (нормативно).** Среднее считается по всем пользователям инстанса: у нового пользователя своей истории нет, а вопрос «сколько стоит генерация» он задаёт именно до первой. Это не персональные данные — агрегат по деньгам оператора, а не по чужим проектам.

## Consequences

**Плюсы:**
- Приложение получает обе величины из уже существующих данных: ни новых таблиц, ни миграций, ни фонового пересчёта.
- `cost_usd` берётся из того же агрегата, что и budget-гард, — расхождения «клиент видит одно, гард считает другое» конструктивно нет.
- Обе величины read-only и не участвуют в решениях биллинга: ошибка в них не может привести к неверному начислению или отказу в квоте.

**Минусы:**
- `avg_generation_cost_usd` считается запросом на каждый `GET /billing/me` (частый эндпоинт клиента) по `generation_jobs` без индекса на `created_at`. При текущих объёмах это дешёвый seq scan по небольшой таблице; при росте — кандидат на индекс или кэш с TTL, контракт при этом не меняется.
- Среднее по сервису делится между всеми пользователями инстанса: оператор раскрывает клиенту порядок своей себестоимости. Принято сознательно — это и есть смысл поля.
- Величины в USD без пересчёта в валюту пользователя; локализация цены — задача клиента.

## Alternatives

- **Только `cost_usd` задачи.** Отвергнута владельцем: не отвечает на вопрос «сколько стоит генерация» до её запуска.
- **Среднее по конкретному пользователю.** Отвергнута: у нового пользователя история пуста — поле было бы `null` именно тогда, когда нужнее всего.
- **Считать `cost_usd` заново из `llm_usage` при каждом запросе.** Отвергнута: второй источник той же величины, расхождение с budget-гардом — вопрос времени.
- **Отдавать стоимость в токенах вместо USD.** Отвергнута: токен в этом продукте — единица квоты пользователя (1 токен = 1 генерация, [ADR-038](ADR-038-adapty-consumable-token-packs.md)), а вопрос был про деньги; смешение единиц в одном поле путало бы клиента.
