# ADR-051 — Выбор модели генерации пользователем: каталог `GET /models` + `model_id` на проекте

**Статус:** Accepted · **Дата:** 2026-09-07 · **Sprint:** клиентский API (третья ось выбора)

Добавляет пользовательский каталог моделей, необязательное поле `model_id` в `POST /projects` и колонку `projects.model_id`. Пайплайн, биллинг и квоты не меняет; агенты получают модель параметром вместо чтения `Settings` напрямую.

## Context

Сайт строят **четыре агента**: `agent1` (интервью), `agent2` (спека), `agent3` (сборка дерева), `agent4` (правки и починка). У каждого своя модель из `AGENTn_MODEL`, и значения намеренно разные — спека пишется более сильной моделью, чем интервью ([ADR-023](ADR-023-agent-token-budget.md), [ADR-032 §2](ADR-032-llm-provider-abstraction-openai.md)).

Сменить модель можно было только правкой `.env` инстанса с рестартом api и worker: `get_settings()` кэширован (`lru_cache`), а агенты читали `settings.agentN_model` внутри себя.

Первая формулировка задачи звучала как «эндпоинт, чтобы обновить модель всех агентов», и была реализована как админская ручка с таблицей оверрайдов. Владелец уточнил: это должен быть **обычный пользовательский** выбор — «чтобы пользователь мог выбрать модель». Админский вариант откачен целиком, здесь зафиксирован пользовательский.

## Decision

### A. Каталог пресетов, а не свободный идентификатор модели

`GET /models` отдаёт карточки `{id, title, description}`; выбор передаётся в `POST /projects` полем `model_id`. Элемент каталога — **пресет**: выбранная модель применяется ко всем четырём агентам сразу.

- **Почему каталог, а не сырое имя модели.** Опечатка в идентификаторе выяснилась бы только при вызове провайдера — то есть уже внутри оплаченной задачи, отказом посреди генерации. Каталог даёт `422` на входе.
- **Почему пресет на всех агентов, а не поле на каждого.** Пользователь выбирает «быстрее или качественнее», а не раскладку моделей по шагам пайплайна; per-agent настройка — операторская задача и остаётся за `AGENTn_MODEL`.
- **Каталог провайдер-специфичен.** Под одним и тем же `id` (`fast`/`quality`) на anthropic-инстансе стоит claude-модель, на openai-инстансе — GPT ([ADR-032](ADR-032-llm-provider-abstraction-openai.md)). Проверка `model_id` идёт по каталогу **текущего** провайдера, иначе id из чужого каталога молча подставил бы чужую модель.

### B. Выбор живёт на проекте, а не на задаче

`projects.model_id` (nullable, id пресета). Правки и откаты создают новые джобы, и все они обязаны идти на той же модели, что первая генерация: сайт, начатый «качественной» моделью, не должен дорабатываться «быстрой» — иначе правка ломает стиль кода, на который опирался остальной сайт.

Хранится **id пресета**, а не идентификатор модели провайдера: каталог меняется вместе с кодом (новая версия модели — правка `model_service`), а `id` стабилен, и старые проекты автоматически переезжают на актуальную модель своего уровня.

`NULL` — штатное состояние: проект без выбора работает как до этого ADR, каждый агент со своим `AGENTn_MODEL`.

### C. Модель резолвится на каждом шаге и деградирует к окружению

Агенты (`run_agent1`..`run_agent4`, включая редактор) получили необязательный параметр `model`; при `None` берут прежнее значение из `Settings` — инвариант обратной совместимости для тестов и локальных вызовов.

Слой задач резолвит модель **перед каждым вызовом** агента (`_agent_model`), а не один раз на джобу: правка и починка выполняются отдельными тасками и обязаны увидеть выбор проекта. Проект к этому моменту, как правило, уже в identity-map сессии, поэтому лишнего запроса не возникает.

**Устаревший `model_id` не роняет генерацию.** Если пресет исчез из каталога (переименовали, сменили провайдера инстанса), `resolve_agent_model` возвращает значение окружения. Отказ в уже оплаченной задаче из-за изменившегося справочника был бы хуже, чем тихая работа на дефолте; валидация выбора живёт на входе, где отказ ничего не стоит.

## Consequences

**Плюсы:**
- Пользователь выбирает скорость/качество сам, тем же способом, что шаблон и стиль — третья карточка на том же экране.
- Смена модели больше не требует рестарта: достаточно выбрать пресет; операторский путь (`AGENTn_MODEL` + рестарт) остался как дефолт инстанса.
- Выбор фиксирован на проекте, поэтому правки не «перескакивают» на другую модель.
- Ни один денежный путь не затронут: списание, лимиты и `cost_tokens` от выбора не зависят.

**Минусы:**
- Цена генерации для пользователя одинакова (1 токен), а себестоимость `quality`-пресета выше — экономика инстанса зависит от того, что выбирают пользователи. Если перекос станет заметным, потребуется разная цена в токенах по пресетам.
- Каталог правится только деплоем: новый уровень модели — коммит, как и у шаблонов со стилями.
- `title`/`description` одноязычны (описания на русском, названия английские) — локализации в контракте нет.
- Резолв делает `session.get(Project, ...)` на каждом шаге; при холодной сессии это дополнительный SELECT по первичному ключу.

## Alternatives

- **Админская ручка «сменить модель всем агентам» (первая реализация).** Отвергнута владельцем: нужен пользовательский выбор, а не операторская настройка. Таблица оверрайдов и сервис удалены до коммита.
- **Сохранённая настройка пользователя (`PUT /me/model`).** Отвергнута владельцем в пользу выбора на запуск: настройка профиля не даёт сделать один проект быстрым, а другой качественным.
- **`model_id` на джобе, а не на проекте.** Позволял бы менять модель между правками — ровно то, чего §B избегает.
- **Свободный идентификатор модели от клиента.** Гибко, но переносит цену опечатки в середину оплаченной генерации.
- **Каталог в БД с админ-редактированием.** Преждевременно: два пресета не оправдывают таблицу и CRUD — та же логика, что для шаблонов ([ADR-048](ADR-048-site-templates-catalog.md)) и стилей ([ADR-050](ADR-050-site-visual-styles.md)).
